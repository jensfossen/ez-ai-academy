# Agents and Harness Engineering Exercise Bank

Select scenarios close to the learner's work. Use synthetic, redacted, or approved inputs. Make the learner name or update a setup, run or simulate a request against it, inspect the output, and revise the *harness* based on evidence.

These H1–H5 activities are **formative practice**. They teach the sequence. They are not a substitute for the [three-part completion contract](#completion-evidence) at the bottom of this file.

If a learner pastes confidential, personal, regulated, or proprietary material, stop using it and retry with a synthetic stand-in (`resources/enterprise-baseline.md`).

Stay inside Module 4 vocabulary. If the learner only rewrites the request or restacks the pack, ask whether the tools, rules, memory, files, or interface caused the miss.

## H1 — Agent versus harness

Present one talk-only chat next to a helper that can take a workplace step:

- “It only chats — there’s no setup.” (the chat box is already a harness with few permissions)
- “Draft Friday’s status note from the project folder.” (folder access is a harness choice)
- “Find the open risks and list them.” (searching a file is a step; the helper is goal-seeking)

Ask the learner which part is the agent and which part is the harness. Grade only after they name a chat box with no tools as still a harness.

## H2 — Tools and permissions

Provide four capabilities, only one of which belongs for a draft-only status note. Ask the learner to keep the needed tool, withhold extra permission, and say what a person still does.

Synthetic set (use as written or adapt the *shape*):

1. Open the project folder (needed).
2. Draft the status note (needed action).
3. Send-email to the sponsor list (extra unless sending is the job).
4. Calendar + every shared drive (extra).

A useful withheld permission is send-email. A useful person-owned step is “review, then send.”

## H3 — Rules that stay on

Scenario: The helper may draft a customer reply from approved notes. Accuracy and a human send matter more than looking finished.

Ask the learner to write one standing rule a teammate could follow next week. Do not reward “be careful” as the only control.

## H4 — Memory and files

Use one job and a mixed standing set: this week’s approved change summary, last month’s joke channel, and an old org chart. Ask the learner which file the helper may see, what they would clear from memory, and how they would note that the setup was tightened.

## H5 — Diagnose the setup before revising the request

Run a request against the learner's setup. Before scoring, ask:

1. What did the output do well?
2. What is the most consequential gap?
3. Did that gap come from a vague request, a missing or stale pack, or the setup (tools, rules, memory, files, interface)?
4. Which harness change should address that observed gap?

Compare the learner's diagnosis with `rubrics/interaction-grading.md`. If the miss is only the request, send that repair back to Module 2 language. If it is only the pack, send it back to Module 3 language. Do not pad the prompt or the pack to hide a setup miss.

## Fast-track challenge

Present: “Have the helper handle Friday’s status note.” Include a short synthetic setup that mixes project-folder access with send-email, an open chat, and last month’s joke list in memory.

Ask the learner to name a safer harness, test a request against it, diagnose the output, and update the setup once. Use the dimension scores to route only to lessons that address demonstrated gaps.

Fast-track can *shorten teaching*. It cannot skip the contained exercise at B or above, the workplace application at B or above, or the reusable Harness Working Card.

## Capstone scenario options

Offer examples when the learner cannot choose a real task:

- A weekly status-note helper (project folder; draft only; person sends).
- A customer-reply helper (approved notes only; standing “do not send” rule).
- A meeting-prep helper (this week’s agenda file; no calendar send).
- A policy-into-action helper (current approved policy file; no all-files search).
- A ticket-form helper (short form instead of an open chat that can mail).

Require a second test — a new extra-permission temptation or a different interface — before accepting the reusable artifact.

## Completion evidence

Module 4 is complete only when all three evidence types exist. Use `rubrics/interaction-grading.md` for letter grades. Do not fold formative check scores into the grade.

### 1. Contained exercise — Name or repair a harness, then inspect it

Ask the learner to improve one weak setup (the fast-track mix or an H1–H2 repair), run or simulate a request on synthetic material, and update the harness once from the observed gap.

Look for, without requiring exact words:

1. an agent named separately from the harness;
2. needed tools kept, and extra permissions left off;
3. at least one standing rule a person still owns; and
4. an inspection that drives a setup update, not only a longer request or a thicker pack.

Grade the **setup-and-result interaction**, not how many tools they listed. Coach one improvement at a time and allow a retry. Treat B as the completion threshold for this evidence type.

### 2. Workplace application

Ask the learner to choose one recurring, low-to-moderate-risk task from their role that needs a goal-seeking helper. Have them state:

- the useful result and who will use it;
- which tools and permissions they would give;
- which rule stays on, and what a person still decides;
- what it may remember, and which files it may see;
- how they talk to it; and
- what they would check before using or sending the result.

Then have them run or simulate a request on synthetic, redacted, or approved material and inspect the result.

For product, project, or program work, offer a status-note helper, a customer-reply helper, a meeting-prep helper, or a ticket-form helper as examples. Flag high-impact uses (employment, legal, financial, safety, health, security, or customer commitments) and keep the task in a bounded support shape (`resources/enterprise-baseline.md`).

Grade at B or above before accepting this evidence type.

### 3. Reusable artifact — My Harness Working Card

Co-create this compact artifact in the learner's own words. Confirm they can explain what each part does and what they would change if the job gained send-email tomorrow. A copied list they cannot adapt does not count.

```markdown
# My Harness Working Card

Purpose: <the workplace job this setup supports>

When to use: <recurring situation; who the result is for>

Tools and permissions: <what it may use, and what it may do>

Rules: <must-follow limits; when a person still decides>

Memory: <what it may keep across turns or days>

Files: <which documents it may see>

Interface: <how people talk to it>

Known limitations: <what this setup must not be used for; what a person still checks>
```

Test the card against a second synthetic input or an extra-permission edge case before accepting the artifact. Record a sanitized title and description in `AI_ACADEMY_RECORD`, not confidential file names or live credentials.

# Context Engineering Exercise Bank

Select scenarios close to the learner's work. Use synthetic, redacted, or approved inputs. Make the learner assemble or update a pack, run or simulate a request against it, inspect the output, and revise the *information set* based on evidence.

These C1–C5 activities are **formative practice**. They teach the sequence. They are not a substitute for the [three-part completion contract](#completion-evidence) at the bottom of this file.

If a learner pastes confidential, personal, regulated, or proprietary material, stop using it and retry with a synthetic stand-in (`resources/enterprise-baseline.md`).

Stay inside Module 3 vocabulary. If the learner only rewrites the request, ask whether the sources were needed, current, and enough.

## C1 — Request versus pack

Present one clear request paired with the wrong information set:

- “Write a sponsor brief from these notes.” (the notes are last quarter’s deck)
- “Draft tomorrow’s change note for frontline staff.” (the pack is last year’s process poster)
- “List risks for Friday’s steering meeting.” (the pack is a slogan sheet and a lunch order)

Ask the learner what belongs in the pack versus in the request. Grade only after they name the information set they would use.

## C2 — Needed versus background

Provide five items, only two of which belong in a current pack. Ask the learner to select the needed sources, identify one missing source, and omit background or stale pages.

Synthetic set (use as written or adapt the *shape*):

1. This week’s approved notes from Tuesday’s project meeting.
2. The sponsor wants risks and decisions only.
3. Last month’s already-replaced forecast.
4. The team’s favorite lunch spot.
5. A slogan from last year’s all-hands.

A useful missing source might be “what decision the sponsor must make this week” or “this week’s open risks list if the notes do not name them.”

## C3 — Enough, and what is missing

Scenario: An executive needs a brief by 3 p.m. The approved notes name two risks and no owners. Accuracy matters more than looking complete.

Ask the learner to mark what is missing and decide whether to get that source or keep the unknown visible. Do not reward invented owners.

## C4 — Fresh versus stale

Use one job and two versions of the same source: yesterday’s change summary and this morning’s updated summary. Ask the learner which page stays in the pack, what they would do with the old page, and how they would note that the pack was updated.

## C5 — Diagnose the pack before revising the request

Run a request against the learner's pack. Before scoring, ask:

1. What did the output do well?
2. What is the most consequential gap?
3. Did that gap come from a vague request, or from missing or stale context?
4. Which pack change should address that observed gap?

Compare the learner's diagnosis with `rubrics/interaction-grading.md`. If the miss is only the request, send that repair back to Module 2 language — do not pad the pack.

## Fast-track challenge

Present: “Summarize the customer feedback and tell leadership what to do.” Include a short synthetic set that mixes this week’s approved comments with last quarter’s theme list and a slogan.

Ask the learner to assemble a current pack, test a request against it, diagnose the output, and update the pack once. Use the dimension scores to route only to lessons that address demonstrated gaps.

Fast-track can *shorten teaching*. It cannot skip the contained exercise at B or above, the workplace application at B or above, or the reusable Context Working Card.

## Capstone scenario options

Offer examples when the learner cannot choose a real task:

- A weekly sponsor brief pack (this week’s notes; last week’s deck is stale).
- A policy-into-action pack (current approved policy; last year’s poster is stale).
- A customer-comment theme pack (this week’s approved comments only).
- An executive decision pack (options plus what is still missing).
- A stakeholder change-note pack (this morning’s approved summary).

Require a second test — a new week’s source or a stale-page temptation — before accepting the reusable artifact.

## Completion evidence

Module 3 is complete only when all three evidence types exist. Use `rubrics/interaction-grading.md` for letter grades. Do not fold formative check scores into the grade.

### 1. Contained exercise — Assemble or repair a pack, then inspect it

Ask the learner to improve one weak pack (the fast-track mix or a C1 repair), run or simulate a request on synthetic material, and update the pack once from the observed gap.

Look for, without requiring exact words:

1. an information set named separately from the request;
2. needed sources kept, and background or stale pages left out;
3. at least one missing item marked, not invented; and
4. an inspection that drives a pack update, not only a longer request.

Grade the **pack-and-result interaction**, not pack length. Coach one improvement at a time and allow a retry. Treat B as the completion threshold for this evidence type.

### 2. Workplace application

Ask the learner to choose one recurring, low-to-moderate-risk task from their role that needs a reusable information set. Have them state:

- the useful result and who will use it;
- which sanitized or approved sources they would include;
- which background they would omit;
- what would go stale, and when they would update the pack; and
- what they would check before using the result.

Then have them run or simulate a request on synthetic, redacted, or approved material and inspect the result.

For product, project, or program work, offer a weekly status pack, a change-note pack, a decision brief pack, or a customer-comment pack as examples. Flag high-impact uses (employment, legal, financial, safety, health, security, or customer commitments) and keep the task in a bounded support shape (`resources/enterprise-baseline.md`).

Grade at B or above before accepting this evidence type.

### 3. Reusable artifact — My Context Working Card

Co-create this compact artifact in the learner's own words. Confirm they can explain what each part does and what they would update for a new week or a new task. A copied list they cannot maintain does not count.

```markdown
# My Context Working Card

Purpose: <the useful workplace job this information set supports>

When to use: <recurring situation; who the result is for>

Sources to include: <sanitized or approved sources that change the result>

Sources to omit: <background or extra pages that would bury the needed parts>

How I keep it current: <what I replace, and when / how often>

Missing or stale check: <how I notice the pack is incomplete or out of date before I use a result>

Known limitations: <what this pack must not be used for; what the model may still get wrong>
```

Test the card against a second synthetic input or a stale-source edge case before accepting the artifact. Record a sanitized title and description in `AI_ACADEMY_RECORD`, not confidential source text.

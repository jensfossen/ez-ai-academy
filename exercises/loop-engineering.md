# Loop Engineering Exercise Bank

Select scenarios close to the learner's work. Use synthetic, redacted, or approved inputs. Make the learner name or update a cycle, run or simulate a try against a standard, inspect the output, and revise *one thing* based on evidence.

These L1–L5 activities are **formative practice**. They teach the sequence. They are not a substitute for the [three-part completion contract](#completion-evidence) at the bottom of this file.

If a learner pastes confidential, personal, regulated, or proprietary material, stop using it and retry with a synthetic stand-in (`resources/enterprise-baseline.md`).

Stay inside Module 5 vocabulary. If the learner only rewrites the request, restacks the pack, or retunes the harness, ask whether they had a checkable standard, one change, and a stop rule.

## L1 — Loop versus longer chat

Present one taste-driven rewrite next to a measured cycle:

- “Keep rewriting Friday’s note until it feels right.” (taste, not a loop)
- “Try once, check ‘risks and decisions only, no invented owners,’ stop when it matches.” (a measured cycle)
- “What does RACI mean in this deck?” (a one-off question; no loop needed)

Ask the learner which job needs a loop and which part is the cycle. Grade only after they name a one-off chat as not requiring a loop.

## L2 — Standard and evidence

Provide four lines, only some of which are a checkable standard. Ask the learner to keep the standard, name the evidence, and drop fluency-as-proof.

Synthetic set (use as written or adapt the *shape*):

1. This week’s approved notes only (standard + evidence).
2. Risks and decisions; no invented owners (standard).
3. Draft only; a person sends (standard).
4. “Sounds executive” / “looks good” (not a standard).

A useful missing piece is “what I will look at” if they kept 1–3 but named no evidence.

## L3 — Change one thing

Scenario: The draft invented an owner. Accuracy matters more than looking finished.

Ask the learner to name one change for the next try and the same standard they will check. Do not reward changing tone, pack, and send-email together.

## L4 — Stop rule

Use one job that now meets the list: Friday’s note includes risks and decisions, invents no owners, and a person would send it. Someone wants three more rounds “to make it sparkle.” Ask the learner what the stop rule is, and whether they would stop.

## L5 — Diagnose whether a loop is the job

Run a request against the learner's cycle. Before scoring, ask:

1. What did the output do well?
2. What is the most consequential gap?
3. Did that gap come from a vague request, a missing or stale pack, a weak setup, or a missing standard / one-change / stop rule?
4. Was this repeatable work, or a one-off chat?
5. Which one cycle change should address that observed gap — or should they stop?

Compare the learner's diagnosis with `rubrics/interaction-grading.md`. If the miss is only the request, send that repair back to Module 2 language. If it is only the pack, Module 3. If it is only the setup, Module 4. If work is dropping between several helpers, offer Graph Engineering — do not invent stations here. Do not pad the prompt to hide a missing standard.

## Fast-track challenge

Present: “Have the helper handle Friday’s status note until it is great.” Include a short synthetic mix: no written standard, three simultaneous changes (tone, last quarter’s deck, send-email), and a plan to keep going until it sparkles.

Ask the learner to name a measured cycle, test one try against a standard, diagnose the output, and change one thing. Use the dimension scores to route only to lessons that address demonstrated gaps.

Fast-track can *shorten teaching*. It cannot skip the contained exercise at B or above, the workplace application at B or above, or the reusable Loop Working Card.

## Capstone scenario options

Offer examples when the learner cannot choose a real task:

- A weekly status-note cycle (this week’s notes; no invented owners; stop when a person would send).
- A customer-reply cycle (approved notes only; draft only; one wording change after a miss).
- A meeting-prep cycle (this week’s agenda; stop when the three open questions are listed).
- A policy-into-action cycle (current approved policy; mark what the policy does not say).
- A change-brief cycle (this morning’s summary; one pack swap if yesterday’s draft leaked in).

Require a second test — a new week’s input or a “keep going until it sparkles” temptation — before accepting the reusable artifact.

## Completion evidence

Module 5 is complete only when all three evidence types exist. Use `rubrics/interaction-grading.md` for letter grades. Do not fold formative check scores into the grade.

### 1. Contained exercise — Run or repair a cycle, then inspect it

Ask the learner to improve one weak cycle (the fast-track mix or an L1–L2 repair), run or simulate a try on synthetic material, and change one thing from the observed gap.

Look for, without requiring exact words:

1. a loop named separately from a longer chat;
2. a checkable standard, and evidence they looked at;
3. one change after a miss, not three; and
4. a stop rule that allows one good pass to be enough.

Grade the **cycle-and-result interaction**, not how many rounds they ran. Coach one improvement at a time and allow a retry. Treat B as the completion threshold for this evidence type.

### 2. Workplace application

Ask the learner to choose one recurring, low-to-moderate-risk task from their role that will happen again. Have them state:

- the useful result and who will use it;
- what they will try;
- the checkable standard, and what evidence they will look at;
- the one thing they would change after a miss;
- the stop rule (when enough); and
- whether this is repeatable work or a one-off chat.

Then have them run or simulate a try on synthetic, redacted, or approved material and inspect the result.

For product, project, or program work, offer a weekly status cycle, a customer-reply cycle, a meeting-prep cycle, or a change-brief cycle as examples. Flag high-impact uses (employment, legal, financial, safety, health, security, or customer commitments) and keep the task in a bounded support shape (`resources/enterprise-baseline.md`).

Grade at B or above before accepting this evidence type.

### 3. Reusable artifact — My Loop Working Card

Co-create this compact artifact in the learner's own words. Confirm they can explain what each part does and what they would change if next week’s notes arrived with a new must-include line. A copied list they cannot adapt does not count.

```markdown
# My Loop Working Card

Purpose: <the workplace job this cycle supports>

When to use: <recurring situation; who the result is for>

Try: <what I run once>

Standard: <what I check against — must include / must not invent / draft-only>

Change one thing: <the single change I make after a miss>

Stop rule: <when one good pass is enough>

Evidence: <what I look at when I check>

Known limitations: <what this cycle must not be used for; one-off chats; what a person still decides>
```

Test the card against a second synthetic input or a “keep going until it sparkles” edge case before accepting the artifact. Record a sanitized title and description in `AI_ACADEMY_RECORD`, not confidential source text or live credentials.

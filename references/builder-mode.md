# Builder Mode and Learner Preview

Use these modes to keep curriculum design separate from course participation.

## Builder Mode

Use Builder Mode when the person is shaping the curriculum, tone, interaction design, content, scoring, or implementation.

- Treat their responses as product feedback, not evidence of learner mastery.
- Research and validate factual content with current authoritative sources. Do not ask the builder to decide which technical answer is correct.
- Ask the builder only for product judgments that genuinely depend on their intent: audience, tone, pacing, tradeoffs, or experience design.
- When showing a sample learner interaction, label it `Sample learner experience` and explain the intended scoring outside the sample.
- Maintain a source note for factual answer keys and safety claims. Prefer standards bodies, primary research, and official technical documentation. Ownership and review for keys and assets: `resources/asset-governance.md`. Sanitation, human-review, accessibility, and privacy for pilots: `resources/enterprise-baseline.md`.

Builder Mode is the default during Academy development unless the person explicitly asks to take the course.

## Learner Preview

Enter Learner Preview only when the person explicitly asks to start, resume, or test the course as a learner.

- Label the transition: `Learner Preview started`.
- Run the Academy normally and treat responses as learner work.
- If the person begins critiquing the experience, pause the lesson and return to Builder Mode.
- Preserve the last learner step so the preview can resume without repeating onboarding.

Use these plain-language controls when helpful:

- `preview as learner`
- `pause preview`
- `return to builder mode`
- `resume preview`

Never mix a curriculum decision request and a graded learner question in the same interaction.

# Module 3 Analogy Cards

Use one or two cards at a time. An analogy is a bridge into the idea, not a complete technical definition. Always pair the helpful comparison with its limit.

If this file is missing (Cowork ZIP), use the analogy already written in the current lesson in `curriculum/context-engineering.md`.

Stay inside Module 3 vocabulary: `context`, `source`, `fresh` / `current`, `enough information`, `background` vs `needed`, `update`, `missing`, and `stale`. Do not introduce retrieval, RAG, agents, windows, or tokens.

## Recommended starting language

**Context is the information set the AI needs for this job — not the wording of the request.** You assemble that set, keep it current, and notice when a weak result came from a missing or stale pack.

This is the default Module 3 mental model. A clearer request does not repair last quarter’s notes.

## A project binder

**Simple version:** The cover note is the request. The pages inside are the context.

**What it explains:** You do not dump the filing cabinet into the binder, and you do not send the cover note with empty pages.

**Where it breaks:** When a needed fact is not in any folder — then you get that source, or you mark it missing.

## Tabs in the binder

**Simple version:** Needed pages change the result. Background tabs bury them.

**What it explains:** The agenda and this week’s figures belong up front. Last year’s slogan and the lunch list do not.

**Where it breaks:** When a “background” page is the only place a required definition lives — then that page is needed.

## A 3 p.m. briefing folder

**Simple version:** If the latest figure is not in the folder, write “figure missing” on the cover. Do not ask someone to guess a confident number.

**What it explains:** Enough information means the pack has what the job cannot safely invent. Missing is not the same as a vague request.

**Where it breaks:** When waiting for the figure would miss the meeting — then you still mark it missing and decide with what you have.

## Last week’s weather report

**Simple version:** Last week’s weather report for today’s outdoor event was once right. Using it today is the mistake.

**What it explains:** A source is current when it is the version the work should use today. Update the pack; do not stack both versions and hope.

**Where it breaks:** When you have no newer report — then you say the source is dated, not that the sky will match last week.

## Yesterday’s stock in the soup

**Simple version:** Taste the soup and realize you used yesterday’s stock. Adding salt will not fix the stock.

**What it explains:** A missing or stale pack is a Context Engineering fix. A vague request is still a Prompt Engineering fix. Check the pack before you add wording.

**Where it breaks:** When the pot was never told it was soup — that is a request problem, not a pack problem.

## Mentor prompt

After showing two analogies, ask:

> “Which comparison would help a coworker remember to update the pack—and where does that comparison stop being accurate?”

Accept a new learner-created analogy when it preserves the two central ideas: the information set is separate from the request, and a weak result can come from missing or stale sources.

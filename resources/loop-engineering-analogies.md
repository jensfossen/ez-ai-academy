# Module 5 Analogy Cards

Use one or two cards at a time. An analogy is a bridge into the idea, not a complete technical definition. Always pair the helpful comparison with its limit.

If this file is missing (Cowork ZIP), use the analogy already written in the current lesson in `curriculum/loop-engineering.md`.

Stay inside Module 5 vocabulary: `loop` / measured cycle, `try`, `check` / standard, `change one thing`, `repeat`, `enough` / when to stop, and `evidence` / what you looked at. Do not introduce GraphRAG, frameworks, experiment platforms, windows, or tokens.

## Recommended starting language

**A loop is a measured cycle: try, check against a standard, change one thing, try again.** One good pass can be enough. Loops are for repeatable work, not every chat.

This is the default Module 5 mental model. A clearer request does not replace a missing standard. A current pack does not replace a stop rule.

## Taste the soup, then add one pinch

**Simple version:** Tasting is the check. One pinch is the change. Serving when it matches the recipe is enough.

**What it explains:** A loop is a cycle, not a longer chat. One good pass can be enough.

**Where it breaks:** When you are only asking where the spoons are — that is a one-off question, not a batch.

## A recipe card with a taste test

**Simple version:** “Salty enough for this table” is a standard. “Make it nicer” is not.

**What it explains:** A standard is something you can look at. Fluency is not a standard. Name the evidence.

**Where it breaks:** When the card never named salt — then write the standard first.

## One knob on the radio

**Simple version:** If the station is wrong, turn one knob. Twisting bass, volume, and tuner together hides which move found the station.

**What it explains:** Change one thing per cycle. Changing three things hides what worked.

**Where it breaks:** When two knobs are actually one control — then name that one control.

## When the batch is good enough to serve

**Simple version:** You do not keep stirring because stirring feels productive.

**What it explains:** Enough is a stop rule you wrote in advance. One good pass can be enough.

**Where it breaks:** When the table’s rule changed — then update the standard, do not guess.

## A weekly bake versus asking where the cups are

**Simple version:** The bake can use a taste-and-adjust cycle. The cups question is one ask.

**What it explains:** Loops are for repeatable work. A one-off question needs a clear request, not a measured cycle.

**Where it breaks:** When two bakers keep dropping the recipe card — that handoff is Graph Engineering, not a second loop on the same batter.

## Mentor prompt

After showing two analogies, ask:

> “Which comparison would help a coworker remember that one good pass can be enough—and where does that comparison stop being accurate?”

Accept a new learner-created analogy when it preserves the two central ideas: a loop needs a checkable standard and one change, and not every chat needs a loop.
